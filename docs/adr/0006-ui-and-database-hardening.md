# ADR 0006 - UI and database hardening

- Date: 2026-10-30. Phase 06 / MVP2. Status: Implemented; formal human phase acceptance not recorded. Contributor: user and Codex.
- Context: the exercise needs a concise human discount workflow and reproducible synthetic data, without presenting exercise defaults as bank policy. It must retain historical reviewed terms and remain usable without AI.
- Decision: use the same-origin workspace with direct Manager/Reviewer switching, ten fictional applications assigned to Ada, and Blake as reviewer. Add nullable, bounded loan amount, property value, standard rate and term to applications; seed missing fictional values and prefill editable versioned request context. Preserve submitted snapshots and decisions. Retired demo actors with history stop reconciliation instead of being deleted. Use isolated synthetic storage to verify setup, restart and backup.
- Alternatives: keep the original selector and fewer applications; require repeated manual entry; overwrite saved values or remove historical actors; bundle AI for core use. These were rejected to reduce friction, preserve data and keep the core portable.
- Consequences: legacy application financial fields can remain null until populated; seed conflicts involving historical actors require deliberate handling. Demo identity is not production authentication. Review a different database/deployment approach for multi-instance production and establish real policy and access controls separately. Optional model integration belongs to Phase 09.
